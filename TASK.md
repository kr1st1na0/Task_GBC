# Домашнее задание: сервис фоновой обработки заказов

## Цель
Сделать веб-сервис, который принимает файл с заказами, обрабатывает его в фоне через очередь задач и отдаёт клиенту статус и результат.

## Исходные данные
Файл `orders.json` (200 заказов книжного магазина). Пример записи:

```json
{
  "order_id": 1001,
  "customer": "maria",
  "product": "Война и мир",
  "amount": 19.93,
  "currency": "USD",
  "order_date": "2026-09-14",
  "review": "Отличная книга, читал не отрываясь"
}
```

В файле есть несколько «битых» записей (нет поля, неизвестная валюта, дубликат). Сервис должен с ними справляться, а не падать.

## Технические требования

### Развёртывание
1. Всё запускается командой `docker compose up`, один compose-файл.
2. Компоненты: **API** (FastAPI), **брокер** (Redis или RabbitMQ), **воркер**, **хранилище** результатов (PostgreSQL или Redis).
3. Очередь задач на выбор: **Celery / TaskIQ** или **FastStream**.
4. В README в разделе «Выбор инструмента» (3–5 предложений) напишите: что выбрали, почему он подошёл, какой минус заметили.

### Функциональные требования
1. `POST /jobs`: загрузка файла. Ответ: `202 Accepted` и `job_id`. Обработка идёт в фоне.
2. `GET /jobs/{id}`: статус (`pending / running / done / failed`) и прогресс (обработано N из M).
3. `GET /jobs/{id}/result`: результат в формате JSON (пример структуры ниже). Только для завершённых задач; для остальных ответ с понятной ошибкой.
   - `GET /jobs/{id}/result?format=csv`: те же обработанные записи в виде CSV-файла (скачивание).

   ```json
   {
     "job_id": "…",
     "status": "done",
     "total": 200,
     "processed": 197,
     "failed": 3,
     "summary": { "...": "таблицы сводки, см. пункт 5" },
     "errors": [
       {"order_id": 1010, "reason": "amount is missing"}
     ]
   }
   ```
4. **Обработка записей: выберите один вариант.**

   **Вариант A. Анализ отзывов**

   Для каждого заказа по полю `review` определите:
   - количество слов;
   - язык: `ru` или `en`;
   - тему по ключевым словам: `delivery` (доставка), `quality` (качество печати), `plot` (сюжет) или `other`. Словарь ключевых слов составьте сами.

   Сводка по файлу (на pandas или polars, см. пункт 5):
   - таблица «тема × язык»: число отзывов и средняя длина в словах;
   - динамика: число отзывов по неделям (по `order_date`);
   - топ-10 слов.

   **Вариант B. Конвертация валют**

   Для каждого заказа приведите `amount` к USD по курсу на дату `order_date`. Курсы берите из публичного API без ключа, например [currency-api](https://github.com/fawazahmed0/exchange-api): `https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@{YYYY-MM-DD}/v1/currencies/usd.json`.

   Нужны таймаут и повтор запроса при сетевой ошибке или ответе 5xx.

   Сводка по файлу (на pandas или polars, см. пункт 5):
   - таблица «клиент × исходная валюта»: сумма в USD;
   - топ-3 клиента по сумме;
   - динамика: сумма в USD по неделям (по `order_date`);
   - общая сумма и средний чек.

5. Сводка и выгрузка на **pandas или polars**. Обработка записей идёт задачами в очереди, а когда все записи готовы, отдельная финальная задача:
   - собирает результаты обработки в DataFrame (колонки не должны быть «сырыми»: приведите даты к типу даты, числа к числам);
   - считает таблицы сводки из варианта A или B;
   - сохраняет сводку (в JSON) и записи (для CSV) в хранилище.

   Циклы по записям для подсчёта сводки не подойдут. В README в одном предложении напишите, почему выбрали pandas или polars.
6. Ошибки:
   - при временной ошибке задача повторяется (retry с паузой между попытками);
   - ошибка в одной записи не роняет весь job: запись попадает в список ошибок с причиной;
   - как вы обработали дубликат `order_id`, опишите в README.
7. Авторизация по API-ключу: пользователь видит только свои задачи.

### Бонусы (необязательно)
- Flower (для Celery) или простая страница-дашборд со списком задач и их статусами.
- Тесты на pytest.
- Повторная загрузка того же файла не создаёт новую работу.
- Реализовать оба варианта обработки.

## Темы для подготовки к обсуждению
Это направления для самостоятельного изучения. На собеседовании мы обсудим их своими словами; заученные определения не нужны. Если чего-то не знаете, так и скажите.

1. **Авторизация.** Как приложения узнают, кто пользователь и что ему разрешено. Основные подходы и их отличия, как безопасно хранить пароли и как не показать пользователю чужие данные.
2. **Асинхронность, потоки и процессы.** Как Python выполняет несколько дел одновременно, какие подходы для каких задач подходят и какие ограничения есть у каждого.

4. **Отладка приложения в Docker.** Как устроена работа с контейнерами и как искать причину, если что-то в приложении из нескольких сервисов перестало работать.
